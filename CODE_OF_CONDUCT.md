# Code of Conduct

## Our pledge

We as members, contributors and maintainers pledge to make participation in
this project a harassment-free experience for everyone, regardless of age, body
size, visible or invisible disability, ethnicity, sex characteristics, gender
identity and expression, level of experience, education, socio-economic status,
nationality, personal appearance, race, religion, or sexual identity and
orientation.

We pledge to act and interact in ways that contribute to an open, welcoming,
diverse, inclusive and healthy community.

## Why this matters here especially

This is a learning project. Everyone here is going to push a broken commit,
misunderstand a git command, or open a pull request that does not work. That is
the entire point. Nobody gets made to feel stupid for it.

## Our standards

Examples of behaviour that contributes to a positive environment:

* Being kind and patient with people who are new to this
* Reviewing someone's code, not someone's character
* Saying "here is what I would change and why" rather than "this is wrong"
* Accepting a review comment without taking it personally
* Asking a question in Discussions instead of guessing silently
* Giving credit — co-authoring a commit when someone genuinely helped

Examples of unacceptable behaviour:

* Harassment, insults, or personal attacks of any kind
* Sexualised language or imagery, or unwelcome sexual attention
* Publishing someone else's private information — including their **email
  address** — without their explicit permission
* Dismissing or mocking a beginner's question
* Deliberately breaking `main`, deleting others' branches, or force-pushing
  over someone else's work
* Any other conduct which could reasonably be considered inappropriate in a
  professional setting

## Project-specific rules

This project exists partly so that participants can earn GitHub profile
achievements. Those achievements must be earned honestly:

* **No fake activity.** No empty commits, no meaningless changes, no pull
  requests opened purely to move a counter.
* **No spamming strangers.** Do not ask people outside this project to star the
  repository, and do not post about it in unrelated issues, Discussions or
  repositories.
* **No manufactured popularity.** Do not use alternate accounts, and do not
  trade stars with other projects.
* **No fake questions.** A GitHub Discussion should be a real question you
  actually had. An answer is marked as accepted only when it genuinely solved
  the problem.

Breaking these rules risks the accounts of everyone involved and defeats the
purpose of the project. It is treated as a Code of Conduct violation.

## Enforcement responsibilities

The repository owner is responsible for clarifying and enforcing these
standards, and will take fair corrective action in response to any behaviour
they deem inappropriate, threatening, offensive or harmful. They have the right
to remove, edit or reject comments, commits, code, issues and pull requests that
are not aligned to this Code of Conduct.

## Scope

This Code of Conduct applies within all project spaces — the repository,
issues, pull requests, Discussions and code review — and also applies when an
individual is officially representing the project in public spaces.

## Reporting

If you experience or witness unacceptable behaviour, report it to the
repository owner. Since this is a small group, the fastest routes are:

1. Send the repository owner a **direct message** on whatever platform your
   group already uses.
2. Or open a **private security advisory** on this repository
   (`Security` tab → `Report a vulnerability`), which is visible only to the
   repository owner. It is not really a security report, but it is the only
   private channel GitHub gives a public repository, and it works.

Do not report a Code of Conduct concern in a public issue.

All reports will be reviewed and investigated promptly and fairly. The reporter's
privacy and security will be respected.

## Enforcement guidelines

The repository owner will follow these guidelines in determining consequences:

**1. Correction** — a private, written warning explaining why the behaviour was
inappropriate. A public apology may be requested.

**2. Warning** — a warning with consequences for continued behaviour. No
interaction with the people involved for a specified period.

**3. Temporary ban** — a temporary ban from any interaction with the project.

**4. Permanent ban** — a permanent ban from any interaction with the project.
